## 5. (기술) 저장소 공통화 + 동시쓰기 안전장치 + 자동 백업

**배경**: `load_settings()`/`save_settings()` 패턴이 `member_link.py`/`raid_config.py`/`raid_signup.py`/`notice.py`/`web/admin.py` 등 여러 파일에 각자 복붙돼 있음. 봇 프로세스와 웹 프로세스가 동시에 `guild_settings.json`을 읽고 쓰는데 파일 잠금이 없어서, 실사용자 여러 명이 동시에 제출하면 한쪽 저장이 다른 쪽을 덮어쓸 위험이 있음. 백업도 전혀 없어서 파일 손상 시 전체 길드 데이터 유실 위험.

**결정**: 계획에 포함.

- `bot/utils/storage.py`(가칭) 신규 — `load_settings()`/`save_settings()`를 한 곳으로 모으고, 여러 파일의 중복 정의를 이걸 import하는 걸로 교체.
- 저장 시 파일 잠금(간단한 lock 파일 방식이나 `filelock` 라이브러리) 적용 — 동시 쓰기 충돌 방지.
- 저장할 때마다 `bot/data/backups/guild_settings_YYYYMMDD_HHMMSS.json` 형태로 타임스탬프 백업 남기고, 오래된 것부터 자동 정리(예: 최근 N개만 유지).

## 6. (기술) 로스트아크 API 키 확대

**배경**: 지금 `.env`의 `LOSTARK_API_KEYS`에 1개뿐(라운드로빈 풀이 작음). 실제 여러 길드가 동시에 캐릭터/원정대 조회하면 레이트리밋(429)에 금방 걸릴 수 있음.

**결정**: 계획에 포함.

- 코드 자체는 이미 콤마로 구분된 여러 키를 라운드로빈으로 도는 걸 지원함(`bot/utils/lostark_api.py`의 `APIKeyManager`) — **키 발급 자체는 사용자 몫**(개발자 포털에서 추가 발급), `.env`에 콤마로 추가만 하면 바로 적용됨.
- 시범가동 규모(길드 수·동시 사용자 수) 감안해서 몇 개가 적정한지는 실제 가동 직전에 트래픽 추정하며 같이 정하기.

**배경**: 지금은 개발 PC에서 수동으로 봇/웹을 띄워둔 상태라, PC가 꺼지거나 재부팅되면 서비스가 전부 멈춤(이번 세션 중에도 실제로 멈췄다가 다시 켠 적 있음). 9~10월 시범가동 전에 상시 가동되는 실제 호스팅으로 옮겨야 함.

**결정**: 계획에 포함.

- 우선 준비할 것(호스팅 업체 선택 전에 가능한 것들):
  - 프로세스 상시 실행 방식 정리(예: systemd 서비스화 또는 pm2 등 — 지금처럼 터미널 창 띄워두는 방식에서 벗어나기)
