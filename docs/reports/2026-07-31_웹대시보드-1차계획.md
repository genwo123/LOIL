# 2026-07-31 — 웹 대시보드 1차 구현계획

## 배경
로일을 "전반적인 시스템을 웹으로 이동" 하는 큰 방향으로 가기로 했고, 그 첫 단계로 **관리자(길드장/부길드장) 로그인 + 일정 관리**를 웹으로 옮기기로 결정.

## 결정된 것
| 항목 | 결정 |
|---|---|
| 로그인 방식 | Discord OAuth2 (대표만 로그인) |
| 길드 등록 | 별도 신청/승인 없음 — 봇 초대 + 대표 OAuth 로그인이면 끝 |
| 길드원 | 로그인 불필요, 지금처럼 링크(`/g/{slug}`)로 조회만 |
| 데이터 저장 | JSON(`guild_settings.json`, Google Sheets) 그대로 먼저 검증, 되면 MySQL로 합침 |
| 웹 범위(1차) | 일정 조회·추가·수정·삭제만. 파티 자동 편성 이관은 다음 라운드 |

## 왜 이 순서인가
- 승인 게이트(길드 등록 승인, 총무 권한 위임)는 지금 1~2개 길드 시범 운영 단계에서는 과함 → 시범 운영 후 반응 보고 필요하면 2차·3차로 추가
- 개인화(길드원별 웹 로그인)도 지금은 보류 — `/내정보` 등 Discord 명령어로 이미 해결되고 있고, `/g/{slug}` 페이지의 "내 일정" 탭이 로그인 없이도 충분히 동작

## 1차에서 만들 것
- `web/auth.py` — Discord OAuth2 로그인/콜백/유저·길드 조회
- `web/admin.py` — 로그인 필요 라우트 (길드 선택, 일정 조회/추가/수정/삭제)
- `web/templates/login.html`, `guild_select.html`, `admin_schedule.html`
- 일정 CRUD는 새로 안 만들고 기존 `bot/utils/sheets.py`의 `add_raid`/`update_raid`/`delete_raid`/`get_all_data` 재사용 (Sheets가 계속 source of truth)
- `.env` 추가: `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_REDIRECT_URI`, `SESSION_SECRET_KEY`
- `requirements.txt` 추가: `itsdangerous`

## 빌드 순서
1. Discord OAuth2 로그인 왕복 연결 (로그인 → 콜백 → 세션 저장)
2. 관리 가능한 길드 판별 (OAuth 길드 목록 ∩ `guild_settings.json`에 이미 있는 길드)
3. 길드 선택 → 일정 조회 화면 (읽기)
4. 추가·수정·삭제 붙이기 (쓰기)
5. 로그아웃 / 세션 만료 처리

## 검증 방법
로컬에서 `uvicorn web.main:app --reload` 띄우고 실제 로일 디스코드 계정으로 로그인 → 길드 목록 확인 → 웹에서 일정 추가 → Google Sheets에 실제 반영되는지 → Discord `/일정조회`에서도 그대로 보이는지 확인.
