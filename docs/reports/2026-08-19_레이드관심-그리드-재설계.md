# 2026-08-19 — 레이드 관심 UI + 캐릭터 등록 재설계

## 배경

기존 "관심 있는 레이드" 화면(요일별 카드 세로 나열 + 체크 시 드롭다운)에 대해 사용자 피드백:
- "저렇게 하면 안 될 것 같다" — 세로 카드 나열 방식이 별로임.
- 예전에 언급했던 "피자 테이블"(겹치는 체크박스 그리드) 개념을 레이드에도 적용하거나,
  다른 사이트들처럼 레벨 기준 자동 추천을 적용하는 쪽을 원함.
- 캐릭터 목록은 시트 닉네임으로 로스트아크 API를 조회하는 지금 방식이 닉네임 불일치로 계속 실패
  → 대표 캐릭터 하나만 등록받고, 원정대(siblings) API로 전체 캐릭터를 가져와 레벨 높은 순 6개로
  정렬해서 쓰자는 제안.

## 확정된 방향 (사용자 확인 완료)

1. **대표 캐릭터명 등록 위치**: 새 Discord 명령어 대신, 기존 "내 시트 연결" 흐름(시트 탭 선택 직후)에
   이어서 등록. 시트 탭 선택 → 대표 캐릭터명 입력 모달(선택 입력, 비우면 시트 탭 이름 그대로 사용) →
   저장 완료 메시지.
2. **레이드 관심 그리드**: 한 레이드에 캐릭터를 여러 개 체크 가능(메인/부캐 둘 다 의향 있으면 둘 다 체크,
   최종 조율은 관리자 몫).

## 구현 계획

### `bot/utils/member_link.py`
- `set_main_character(guild_id, user_id, name)` / `get_main_character(guild_id, user_id)` 추가.
  저장 구조: `guild_settings.json[gid]["characters"] = {discord_user_id: 캐릭터명}` (기존 `members`와 병렬).

### `bot/cogs/notice.py`
- `LinkStep2View.on_select`: `set_sheet_name` 저장 후 메시지 전송 대신 `CharacterNameModal`을 응답으로 띄움
  (선택 입력 텍스트필드 1개). 모달 제출 시 값 있으면 `set_main_character` 저장, 최종 확인 메시지에
  시트 탭 + (입력했다면) 대표 캐릭터명 같이 표시.

### `bot/utils/raid_signup.py`
- 기존 `set_interest`(레이드당 캐릭터 1명, 덮어쓰기)를 `set_member_interests(guild_id, sheet_name, selections)`로
  교체 — 이 사람의 전체 관심 목록(여러 레이드 × 여러 캐릭터 가능)을 한 번에 통째로 교체.
- `get_interest`/`get_all_interest`는 구조 그대로 유지(엔트리가 사람당 여러 개 가능해짐).

### `web/availability.py`
- 캐릭터 조회 시 `get_main_character(guild_id, user_id)`가 있으면 그걸로, 없으면 기존처럼 `sheet_name`으로
  `get_account_characters` 호출. 결과를 아이템레벨 내림차순 정렬 후 상위 6개만 사용.
- `interest_count`는 (엔트리 수가 아니라) 고유 인원 수로 계산.
- `POST /me/{token}/interest`: 그리드에서 만든 JSON(`raid_key`+`character` 쌍 배열)을 받아
  `set_member_interests` 한 번 호출로 저장.

### `web/templates/availability.html`
- "관심 있는 레이드" 섹션을 그리드로 교체: 행 = 활성 레이드, 열 = 내 캐릭터(상위 6개, 레벨 높은 순).
  각 칸 = 체크박스. 레이드 최소 레벨 미달 캐릭터는 칸이 비활성화(회색, 클릭 불가) — 레벨 기준 자동 추천 역할.
  제출 직전 JS로 체크된 칸들을 `{raid_key, character, item_level}` 배열로 모아 히든 필드에 담아 전송
  (가능시간 그리드에서 쓴 것과 같은 패턴).

## 영향 / 주의사항

- **봇 재시작 필요**: 예 (`notice.py` 모달 로직 변경).
- **웹 서버 재시작 필요**: 예 (`availability.py` 변경).
- 기존에 저장된 `raid_interest` 데이터(레이드당 1명 1캐릭터 구조)는 새 구조에서도 그대로 읽힘(리스트에
  엔트리 1개인 상태일 뿐이라 하위 호환됨) — 마이그레이션 불필요.
- 대표 캐릭터명을 아직 등록 안 한 기존 길드원은 계속 시트 닉네임으로 조회 시도(기존 동작 유지).
