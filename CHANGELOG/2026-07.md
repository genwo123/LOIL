- **미해결**: 실제 유효한 로아 API 키가 없는 상태라 캐릭터 조회 기능(`/내정보`, `/길드전투력`, 파티 평균 전투력)은 여전히 실사용 불가. **사용자가 키를 재발급받아 `⚙│봇설정`에서 다시 등록해야 함.**

#### `bot/cogs/party.py` — 주간 전체 편성 확정 흐름 전면 재설계
- **문제**: 레이드 그룹(세르카 나이트메어/하드/노말, 종막 하드 등)마다 메시지가 따로 오고, 그룹 하나하나마다 저장하기/미정 처리/재편성 버튼을 개별로 눌러야 다음으로 못 넘어감 — 그룹이 여러 개면 그만큼 클릭을 반복해야 하는 구조였음. 사용자가 직접 써보고 "이 불편함을 없애고 싶다"고 요청.
- 사용자와 논의 후 "하나의 통합 화면" 방향으로 결정(그룹별 메시지+버튼 여러 개 → 이미지는 다 모아서 보여주고 확정 컨트롤은 하나로).
- `_save_party_results()` 공통 함수로 추출: 시트 저장 + 시간 저장 로직을 그룹 확정(`PartyGroupConfirmView`)과 통합 확정(`UnifiedConfirmView`)이 공유하도록 정리(기존엔 중복 코드였음).
- `UnifiedConfirmView` 신규: 모든 그룹의 편성 결과를 `{레이드명: 결과}` 하나의 dict로 모아서 관리. 이미지들은 디스코드 메시지당 첨부 10개 제한에 맞춰 여러 메시지로 나눠 한 번에 전송하고, 맨 마지막에 컨트롤 메시지 하나(`✅ 전체 저장` 버튼 + 개별로 손볼 레이드를 고르는 드롭다운)만 붙임.
- `SingleRaidActionView` 신규: 드롭다운에서 레이드 하나를 고르면 그 레이드만 미정 처리하거나 재편성할 수 있는 선택지가 뜸(에페메럴). 재편성하면 새 이미지가 스레드에 추가로 오고, 결과 dict가 갱신되어 "전체 저장"에 반영됨.
- `RaidChecklistView.ai_compose()`(주간 전체 편성 버튼 핸들러)를 이 구조에 맞게 재작성 — 그룹별로 `PartyGroupConfirmView`를 따로 만들던 부분을 전부 제거하고, 결과를 다 모은 뒤 `UnifiedConfirmView` 하나만 생성.
- **개별 레이드 편성**(`IndividualRaidSelectView`)은 원래도 레이드 1개짜리라 이 문제가 없었음 — `PartyGroupConfirmView` 그대로 사용, 손 안 댐.
- **참고**: "재편성"으로 특정 레이드만 다시 짠 경우, 맨 뒤의 주간 일정표 이미지(`_send_weekly`)는 여전히 최초 배정 기준으로 표시될 수 있음(기존 그룹별 방식에서도 있던 동일한 제약이라 이번에 새로 생긴 문제는 아님) — 필요하면 별도로 손봐야 함.

**검증**: `py_compile` 통과. 실제 디스코드에서 첨부파일 10개 초과 케이스(레이드 10개 이상 동시 편성)는 코드 리뷰로만 확인, 실제 테스트 필요.

**봇 재시작 필요**: 예.

### 07/30 — 편성 결과 웹 조회 대시보드 신규 (Discord 이미지 다중 첨부 문제 해결)

**배경**: 사용자가 "디스코드 UI로 한계까지 뽑아낸 건 좋지만 버튼도 너무 많고, 편성 결과도 이미지 여러 장으로 쪼개져서 한 번에 못 준다"고 지적 → 편성 결과를 보여주는 방식만 웹으로 옮기기로 결정 (편성 로직·저장/미정처리/재편성 같은 관리자 액션은 Discord에 그대로 유지, 로그인 없이 길드별 고유 링크로만 접근 구분). 논의 후 확정된 조건: ①조회만 웹, 관리자 액션은 Discord 유지 ②로그인 없음 + 길드별 슬러그 링크 ③기존 Pillow 이미지 재사용 아니고 데이터 기반 HTML 카드 신규 제작 ④배포는 나중, 이번엔 로컬 구조만.
